# D3D12 backend and native gallery

The Windows backend is a CUDA-independent D3D12 compute implementation. It
uses one retained direct queue for compute and raster work, a root-signature
1.0 descriptor table containing exactly 64 bounded UAV slots plus five
bounded read-only mesh/BVH slots, and embedded Shader Model 5.1 bytecode produced
by the Windows SDK FXC.

## Compatibility

The selected adapter must provide Shader Model 5.1 and either:

- Resource Binding Tier 2 or Tier 3; or
- feature level 11_1 or newer when using Resource Binding Tier 1.

This deliberately excludes feature-level 11_0 Tier-1 devices. The native
gallery rejects software adapters unless `--warp` is explicit. Use
`--list-adapters` to print feature level, resource-binding tier, and the
resulting support decision. The tested GTX 1080 reports feature level 12_1 and
Resource Binding Tier 3; Tier 2 would also qualify. NVIDIA hardware is not
otherwise special.

## Runtime contract

`parallel_mater::d3d12::World` mirrors the Metal public surface. Native COM
objects cross the API as opaque pointers in `NativeContext`; the world retains
them. Device views use an opaque `ID3D12Resource` plus byte offset and element
count. Status values preserve the failing `HRESULT` and distinguish adapter
rejection and device removal.

Creation allocates the simulation resources, persistently mapped upload and
readback buffers, a 69-entry descriptor heap (64 UAV descriptors, including
required Tier-1 null descriptors, plus five mesh/BVH SRVs), command allocator/list,
fences, query heap, and timestamp readback. Only one physics frame may be in
flight. A `FrameToken` allocates its wait event when constructed, so
`step_async` itself performs neither allocation nor a CPU wait.

The rigid gate dispatches parallel integration, serial compound/fixed-group
preparation, pair-parallel triangle contact generation with deterministic
CPU-built BVH leaf ordering on hardware, and deterministic colored
contact/constraint reduction for static, kinematic, and dynamic bodies. It supports
fixed, point, hinge, slider, piston, generic, generic-spring, and motor
constraints, including limits, springs, motors, breaking, and collision
suppression. Forces are cleared by compute after the final substep. The
implementation requires no wave operations, double precision, 64-bit shader
atomics, bindless resources, DXR, or vendor extensions.

## Gallery

### Install on Windows

After building Release, install the current user's desktop app and Start menu
entry without administrator access:

```powershell
cmake --build build-d3d12-full --config Release --target install-d3d12-gallery
```

Search Start for **Parallel-Mater**. The native launcher opens the DirectCompute
gallery without a console window. The installer copies the executable, runtime
DLLs, and eight supported scene assets into
`%LOCALAPPDATA%\Programs\Parallel-Mater`; the installed app does not depend on
the source checkout. Rerun the target to update after closing the installed app.
Uninstall through Windows Settings > Apps > Installed apps > Parallel-Mater.
Logs and captures in `%LOCALAPPDATA%\Parallel-Mater` are retained on uninstall.

For an already-built package, run `scripts/Install-WindowsGallery.ps1` with
`-BuildDirectory` pointing to the Release directory containing both executables
and runtime DLLs. Its default is `build-d3d12-full/Release`.

Enable `PARALLEL_MATER_BUILD_D3D12_GALLERY`. The executable uses GLFW with
`GLFW_NO_API`, obtains the native HWND, creates a DXGI flip-model swap chain,
and rasterizes authored rigid meshes with depth, lighting, and colors.
Headless mode uses the same graphics pipeline with an offscreen render target
and writes PPM captures. A native, single-draw bitmap overlay shows the shared
scene catalog and optional FPS, frame-time, and GPU-physics-time panel.

The current upstream catalog has 28 entries. The first eight are available:
Rigid Body, Fixed, Point, Hinge + Slider, Piston, Generic, Motor + Spring, and
the authored Dump Truck. Unsupported entries remain visible but disabled.
The viewer uses `ConstraintMotorSpring.glb` and `DumpTruck.glb`, not the legacy
separate Motor/Generic Spring entries or procedural dump fixture.

Controls: `F` toggles timings; `Tab` opens/closes the catalog; arrows and Enter
or a mouse click select a supported scene. `R` resets, `P` pauses, and Escape
closes the catalog before exiting the app. Drag to orbit, Shift-drag or
right-drag to pan, and scroll to zoom. Outside the catalog, arrow keys tilt
camera-relative gravity, apply a scene-authored force, or drive/steer the
vehicle according to the selected scene. Space releases/restores the Point
constraints or raises/lowers the dump bed. Opening the catalog pauses physics.
Interactive sessions run until closed unless
`--frames` is explicitly supplied; headless sessions default to 240 frames.

Useful commands:

```powershell
parallel-mater-d3d12-gallery --list-adapters
parallel-mater-d3d12-gallery --list-scenes
parallel-mater-d3d12-gallery --adapter 0 --constraint-hinge
parallel-mater-d3d12-gallery --show-fps
parallel-mater-d3d12-gallery --all-rigid-scenes --headless `
  --frames 60 --validate --output captures
parallel-mater-d3d12-gallery --headless --frames 120 --benchmark --output rigid.ppm
```

Use `--repeat 10 --headless --validate` to require identical final handles and
state bits across ten same-adapter runs. `--gpu-validation` additionally enables
the much slower D3D12 GPU-based validation instrumentation. The conformance
runner exposes the rigid-only subset of the shared v1 case registry and compares
each of ten runs with the CUDA goldens using the existing tolerance profiles.

The input-state regression test covers F, Tab, selection, disabled scenes,
reset, pause, and Escape. `tests/d3d12/gallery_input_smoke.ps1` additionally
opens a real window, sends native keyboard events, captures both overlays,
switches scenes, and closes the app. It temporarily brings the viewer forward.

Full CUDA-golden conformance is not yet achieved. WARP retains a dedicated
single-lane solver and raw-triangle contact shader, but previous software
adapter runs have crashed; WARP is not considered validated. Intel/AMD
hardware validation is also outstanding. Do not interpret scene loading or
same-adapter determinism as proof of CUDA parity.

### Current validation and performance

On `main` at `85384f0`, the GTX 1080 build passes the nine selected API,
foundation, controls, registry, comparator, shared-type, and contact-core
tests. The native-window smoke test verifies F, Tab, scene switching, and
Escape. All eight rigid scenes pass ten identical repetitions of two frames
with one substep and the standard D3D12 debug layer; captures are generated.
GPU-based validation has not completed and is not counted as a pass.

The ten-frame default-scene benchmark, with four substeps and no debug layer,
improved from about 787 to 91 ms of GPU physics and from 799 to 97 ms wall
time per frame on this machine. This is still only about 10 FPS, not a
real-time performance claim. Active-pair compaction, stable color lists,
parallel contact preparation, and separate contact/finalization shaders
remove empty-pair work without reducing iterations or substeps. Hinge +
Slider remains slow: about 210 ms per substep in triangle-contact generation.

The frozen v1 input checker reports 27 GLB checksum mismatches against the
latest upstream assets. The analytic `rigid-direct`, `constraint-breaking`,
and `compound-weld-lifecycle` cases also fail frozen CUDA comparisons. No
goldens, tolerances, or asset checksums were changed to mask these failures.

## Staged systems

Fluid/rigid and paint are next, followed by cloth and soft bodies, ropes, and
smoke. Those public methods currently leave outputs unchanged and return
`StatusCode::not_supported`; their signatures will not change as the gates
become functional. `--all-scenes` is reserved and reports that the later gates
are unavailable, while `--all-rigid-scenes` is the first-gate acceptance path.
